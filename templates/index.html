📋 Pipeline Summary — All 5 Exercises

Ex 1 User → app.py (:8080) → FastAPI /ask → Ollama :11434 → codellama:latest → Response
Ex 2 PDFs → chunk_documents.py (1500 chars, 200 overlap) → create_embeddings.py (nomic-embed-text) → 590 chunks · 590 embeddings · 768 dims
Ex 3 Question → nomic-embed-text (query embedding) → Cosine Similarity over 590 vectors → Top-3 chunks → Context + Question → codellama:latest → RAG Answer
Ex 4 retrieval_service.py (:8001) + llm_service.py (:8002) + orchestration_service.py — each a separate FastAPI service communicating via HTTP
Ex 5 Docker: policypal-ai image · orchestration_service on :8000 · host.docker.internal routes to retrieval (:8001) + LLM (:8002) + Ollama (:11434)

📁 Codebase Understanding

Repository-level questions answered by reading the actual PolicyPal source files. The policy-document RAG index does not contain source code — answers come from direct file inspection, not retrieval. Current PolicyPal RAG is optimised for policy-document retrieval. It is not a full repository-aware RAG system.
Limitations: Cross-file reasoning requires AST analysis or a codebase-in-context LLM. Keyword retrieval over policy PDFs cannot answer source-code questions.
